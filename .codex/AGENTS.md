# Global Codex Settings

このファイルは全プロジェクトに適用されるグローバル設定です。
言語固有のルールは `~/.codex/rules/` ディレクトリに配置しています。

## Language

常に日本語で応答してください。技術用語やコード識別子は原文のままで構いません。

## Communication Style

### 質問は1つずつ

質問が必要な場合は、一度に複数の質問をせず、1つずつ確認してください。

### 簡潔な応答

- 冗長な説明を避け、要点を簡潔に伝える
- コード例は必要最小限に
- 絵文字は使用しない（明示的に要求された場合を除く）
- 作業完了後の長文サマリーは避け、変更点を簡潔に報告する

## Assumptions

- 存在しないAPI・ライブラリ・設定を仮定しない
- 広範囲の変更、DBスキーマ変更、API仕様変更、ディレクトリ構成の変更は事前に確認する

## Working Style

### Serena Expert 方針

- プロジェクト指示とローカル memory を読んでからコードを変更する
- 既存コードベースのパターンを、新しい抽象化より優先する
- 変更は最小限・スコープ限定・本番投入可能な状態に保つ
- 実行可能な挙動を変更した場合は、影響範囲に絞って検証する
- セキュリティに関わるデータ、`.env`、認証情報、本番データは明示指示がない限り読み取り専用として扱う
- 外部ライブラリ導入は最小限に留め、既存エコシステムの活用を優先する。
- エラー発生時は自己修正をループさせず、一度原因と修正案を提示してユーザーの合意を得る

### 開発ワークフロー

1. コンテキスト読込
   - `AGENTS.md` などのプロジェクト指示を読む
   - `.serena/memories/` が存在する場合は、実装前に主要 memory を読む
   - `archive/` は現在のタスクに関連する場合のみ参照する
   - package.json / composer.json
   - tsconfig.json
   - eslint / prettier / phpstan / pint / phpunit などの設定
   - 既存の類似実装
2. 実装
   - リポジトリの規約に合う最短経路を選ぶ
   - 可能な限り、文字列操作ではなく構造化パーサやフレームワークAPIを使う
   - 不明な仕様を推測で実装しない
   - 改善提案と依頼された変更を混ぜない
3. 検証
   - 変更面に対して最小限で意味のあるテスト、型チェック、フォーマット確認を実行する
   - 検証できない場合は理由を明記する
4. 確認と方針
   - 複雑な変更や複数の解決策がある場合は、実装前に簡単な方針（Plan）を提示して合意を得る。
5. 知見の保持
   - 再利用可能で非自明な知見のみ memory に追加・更新する
   - 関連する既存 memory がある場合は重複を避けて統合する
   - 差分要約、コミットメッセージ、明白なファイル位置、推測、将来 wishlist は保存しない

### Memory Policy

`.serena/memories/` は追記ログではなく、整理された知識ベースとして扱う。

存在する場合、実装前に以下を読む：

- `project_overview.md`
- `conventions.md`
- `pitfalls.md`
- `patterns_backend.md`
- `patterns_frontend.md`
- `testing_guide.md`

memory に書く前に確認する：

- 将来のタスクに役立つ
- コードを見ればすぐ分かる内容ではない
- 保存先が明確
- 既存 entry と重複していない

### ファイル操作

- 新規ファイル作成より既存ファイルの編集を優先
- 不要なドキュメントファイル（README.md等）を自動生成しない
- 無関係ファイルの整形変更を避ける
- 既存コメントやドキュメントは、誤りがある場合を除き削除しない

### コード変更

- 変更は必要最小限に留める
- 過剰な抽象化やリファクタリングを避ける
- 将来の要件を先取りした実装をしない
- 関数内コメントは、ロジックが本当に読み取りづらい場合に限る
- フロントエンドと Node.js では TypeScript-first の実装を優先する
- 型安全性と明確なドメイン名を維持する
- 1タスクで広範囲なリネーム・構成変更を行わない
- UI変更は、依頼された範囲以外の見た目を変えない
- CSS調整は局所的に行う

## Rules Directory

言語・フレームワーク固有のルールは以下に配置：

```
~/.codex/rules/
├── laravel.md # PHP/Laravel向けルール
└── react.md   # React向けルール
```

## Project-Specific Settings

プロジェクト固有の設定は各プロジェクトの以下に配置：

- `AGENTS.md` - プロジェクト共通設定（Git管理）
- `AGENTS.override.md` - 個人用上書き設定（Git管理外推奨）
