# Issue Fix Infographic Skill

## Goal

仕様・検討結果を、報告・共有・チケット等に貼れる1枚の PNG にまとめる。構成と見た目をそろえ、書き出しを1コマンドにする。
プロジェクトに依存しない（Docker と日本語フォントがあれば動く）。

- 画像は共有用の添付物。プロジェクトの成果物とは分けて、Git 管理外の場所に置く。
- 元になる文書（方針書・仕様書など）は、そのプロジェクトのルールで管理する。画像はそこから作る。

## 1. 構成（固定）

1. ヘッダ: 小見出し（任意）と、1行のタイトル。小見出しは案件名・機能名など。チケット番号などの識別子の指定があれば、「{識別子} / {案件名}」の形にする（指定が無ければ付けない）。
2. 要件・課題と対応案: 左に要件・課題、右に対応案の対を1行ずつ。1つの枠は、見出し1行＋本文2行程度まで。
3. 修正前後の画面（キャプチャがあるときだけ）: 縦長の画面は高さ、横長の画面は幅をそろえて並べる。
4. 結論: 左「確認できたこと」、右「対象外・残課題」。
5. フッタ: 確認した環境の注記。

## 2. 書き方のルール

- 元になる文書を先に読み、内容を写す。新しい主張は足さない。
- 事実と意見を分ける。未確認のものは「推測」「未確認」「実機未確認」と明記する。
- 数値は根拠があるものだけ。目安は「約」を付ける。
- 専門用語には補足を付ける。1文は短く、体言止めか「～する」で終える。
- 1枚に収める。要件・課題と対応案の行は、目安4〜6行（テンプレートは2行なので、足りなければ複製する）。多い場合は、重要なものに絞り、残りは文書側に任せる。
- 元の文書が `issue-fix-list` の書式なら、番号付きの1項目を1行にする。「結論:」「確認結果:」の項目は「確認できたこと」欄、「対象外・残課題」は同名欄に入れる。

## 3. キャプチャの扱い

- ユーザーが貼った画像、またはパスを指定された画像を、作業フォルダにコピーして使う（元の場所の画像は動かさない）。
- 次のものが写っていたら、使う前に報告して判断を仰ぐ。
  - 個人情報・顧客情報・認証情報
  - 開発環境だけの表示（デバッグバー、ローカル URL など）。後者は、画像に添える注記か撮り直しを提案する。

## 4. 作り方

1. 作業フォルダを決める。プロジェクトに Git 管理外の `tmp/` があれば `tmp/{題名}/`（題名は短い英数字の名前。識別子の指定があれば識別子を使う）。無ければ、置き場所をユーザーに確認する（リポジトリ内に作る場合は `.gitignore` に入っているか確認する）。
2. このスキルの `template.html` を、作業フォルダに `infographic.html` としてコピーする。
3. `{{...}}` と、行・カードを埋める。使わない行・修正前後の節は削除、足りなければ複製する。画像は同じフォルダに置き、`img src` を合わせる。
4. 書き出す。`render.sh` は、このスキルの `scripts/` にある。

   ```
   ~/.claude/skills/issue-fix-infographic/scripts/render.sh {作業フォルダ} {題名}_インフォグラフィック.png
   ```

   識別子の指定があれば、出力名は `{識別子}_インフォグラフィック.png` にする。

5. 出力した PNG を Read で開いて確認する（文字の欠け・重なり・画像の見切れ・プレースホルダの残り）。問題があれば HTML を直して再実行する。
6. 完了報告に、出力パスと注意点（キャプチャの映り込みなど）を書く。

## 5. 注意

- 書き出しは Playwright の公式 Docker イメージ（`mcr.microsoft.com/playwright`）を使う。イメージは `PLAYWRIGHT_IMAGE`、npm の playwright のバージョンは `PLAYWRIGHT_VERSION` で変えられる（両方そろえる）。初回は、コンテナ内で playwright の npm パッケージをダウンロードする。
- 日本語フォントは `render.sh` が自動で探し、`fonts.css` を作る。探索順は、環境変数 `JP_FONT_REGULAR` / `JP_FONT_BOLD` → Noto Sans CJK（`/usr/share/fonts/opentype/noto` など）→ 各フォント置き場（`~/.fonts` など）の Noto Sans JP/CJK → `fc-list :lang=ja`。Bold が無ければ Regular で代用する。見つからない場合は `render.sh` がエラーで止まる（Noto Sans CJK の導入か `JP_FONT_REGULAR` の指定が必要）。フォントは作業フォルダへコピーせず、読み取り専用でコンテナに渡す（作業フォルダに残るのは `fonts.css` のみ）。HTML を直して再実行する場合は、`fonts.css` を消さない（再実行で作り直される）。
- コンテナ内の一時ファイルは `--rm` で消える。ホストには、作業フォルダ以外にファイルを残さない。
- 環境によっては、ガードフックが `rm -rf` をブロックする。削除は `rm`（ファイル）か `rm -r`（フォルダ）を使う。
