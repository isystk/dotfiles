# CLAUDE.md ビルダー スキル

## Goal

ユーザーの意図を完全に反映した、高精度なClaude Code用指示書（`.md`形式）を対話形式で作成する。

## 絶対ルール

- **一問一答の厳守**: ユーザーに一度に複数の質問をしない。必ず1つの質問を投げ、回答を受けてから次の質問へ進む。
- **回答の蓄積**: 各回答を内部的に蓄積し、最終的な指示書に反映する。
- **中断対応**: ユーザーから「一旦まとめて」「ここまでで出力して」などの指示があれば、それまでの情報で指示書ドラフトを出力する。
- **出力先の確認**: 最終出力前に、ファイルの保存先（プロジェクトローカル or グローバル）を必ず確認する。

---

## 起動時の動作

スキル起動時、まず以下を宣言してから情報収集を開始する：

```
CLAUDE.md ビルダーを開始します。
一問一答でプロジェクト情報を収集し、最適な指示書を構築します。
「一旦まとめて」と言えばいつでも途中経過を確認できます。
```

---

## 情報収集フェーズ（質問順序）

### Phase 1: 基本情報

**Q1**: このCLAUDE.mdは何のためのプロジェクトですか？（例: Webアプリ開発、データ分析、ライブラリ作成など）

**Q2**: 主な使用言語・フレームワークは何ですか？（例: TypeScript + React、Python + FastAPI、PHP + Laravelなど）

**Q3**: プロジェクトの主要な目標・解決したい課題を一言で教えてください。

### Phase 2: 開発スタイル

**Q4**: コードの応答言語は何語を希望しますか？（日本語 / 英語 / その他）

**Q5**: コミュニケーションスタイルの好みはありますか？（例: 簡潔にまとめて / 詳しく説明して / コードだけ出して、など）

**Q6**: 避けてほしい動作やNGな行動はありますか？（例: 勝手にファイルを削除しない / コメントを書かない / リファクタリングを提案しない、など）

### Phase 3: 技術仕様

**Q7**: コーディング規約・スタイルガイドはありますか？（例: ESLint設定、PSR-12準拠、独自ルールなど）

**Q8**: テストに関する方針はありますか？（例: Jestを使う / テストは書かなくていい / カバレッジ80%以上など）

**Q9**: よく使うコマンドやスクリプトはありますか？（例: `npm run dev`, `./vendor/bin/phpunit`, `docker-compose up`など）

### Phase 4: 制約・注意事項

**Q10**: セキュリティや機密情報に関する注意事項はありますか？（例: `.env`を絶対にコミットしない / 本番DBに直接接続しないなど）

**Q11**: Claudeに与えたい特別な権限、または制限はありますか？（例: git pushは許可しない / npm installは常に許可など）

**Q12**: その他、Claudeへの特別な指示・癖・好みがあれば教えてください。

---

## 出力フェーズ

全質問完了後（または「まとめて」指示を受けた後）、以下を実行する：

### Step 1: 保存先確認

```
指示書の保存先を教えてください：
1. プロジェクトローカル（.claude/CLAUDE.md）
2. グローバル設定（~/.claude/CLAUDE.md への追記）
3. ファイルに保存せず、テキストだけ出力
```

### Step 2: 指示書の生成

収集した情報を元に、以下の構造で指示書を生成する：

```markdown
# プロジェクト情報

[プロジェクト概要・目的]

## 技術スタック

[使用言語・フレームワーク・主要ツール]

## Language / 応答言語

[応答言語の指定]

## Communication Style

[コミュニケーションスタイルの指示]

## Working Style

[開発スタイル・コーディング規約の要点]

### NG行動

[避けてほしい動作のリスト]

## Commands

[よく使うコマンド一覧]

## Security

[セキュリティ・機密情報に関するルール]

## Permissions

[Claudeへの権限・制限設定]

## Additional Notes

[その他の特記事項]
```

### Step 3: ファイル保存（Step 1 で 1 or 2 を選んだ場合）

- プロジェクトローカルの場合: `.claude/CLAUDE.md` に書き込む（ディレクトリが無ければ作成）
- グローバルの場合: `~/.claude/CLAUDE.md` の末尾に追記するか、新規作成する

### Step 4: 完了報告

```
CLAUDE.md を作成しました: [保存パス]

このファイルを編集してさらにカスタマイズできます。
`/claude-md-builder` を再実行すると内容を更新できます。
```

---

## 途中まとめ機能

ユーザーが「一旦まとめて」「現時点で出力」などと言ったとき：

1. それまでに収集した情報を整理して表示
2. 不足している項目をリストアップ
3. 「続けますか？それとも現状で保存しますか？」と確認

---

## 注意事項

- 既存の `CLAUDE.md` がある場合は上書き前に確認する
- 収集した情報は指示書に矛盾なく反映する
- ユーザーの回答が曖昧な場合は、デフォルト値を提案してから進める
- 指示書はユーザーが直接編集できる `.md` 形式で出力する
