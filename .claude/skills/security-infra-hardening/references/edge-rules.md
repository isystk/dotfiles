# エッジ(CDN/WAF)ルールの書き方

Cloudflare を例にする。他の CDN でも「式にホスト条件を入れる」「プラン制限を先に確認する」は共通。

## 1. 共通ルール

- **式は必ず対象ホストの条件から始める**。入れないと、同じゾーン(ドメイン)の全サブドメインに効く。
  - 実例: Cache Rule に `http.host` が無く、別サブドメインのアプリでログアウトが無限ループした
- ブロック系ルールは、国別制限など既存のブロック系の次(先頭側)にまとめる。アクション混在の評価順を避ける
- ルール名は用途が分かる名前にする(例: `UA指紋ブロック`、`認証系レート制限`)
- 設定前に、**ログで誤ブロック候補を実測**する(対象 UA/パスの過去件数。0 件なら安全、正規が混在する UA はブロック対象にしない)
- 画面の表記は変わりやすい。公式の導線(Security → Security rules → Create rule)で探す
- **IPv6 を持つクライアントはアドレスを回して回避できる**。レート制限・IP 拒否・国別制限を IPv4 前提で組むと、IPv6 経路が素通りになる
  - 確認: `dig AAAA <host>`、オリジンの待ち受け `ss -tlnp | grep '\[::\]'`、CDN 側の IPv6 設定
  - IPv6 を数えられないプランなら、その旨と代替(アプリ側の制限を主にする)を記録する。無言で IPv4 のみにしない

## 2. UA ブロック

```
(http.host in {"a.example.com" "b.example.com"})
and (lower(http.user_agent) contains "tool-name" or starts_with(lower(http.user_agent), "other-tool/"))
```

- `lower()` が使えないプランでは外す(大文字小文字は区別される。ツールの既定値が小文字なら実用上問題ない)
- 既定 UA(`curl/`、`python-requests`、`Go-http-client`)は自前の運用スクリプトや正規連携が混在するため、**ブロック対象にしない**
- 攻撃本体は既定 UA を使うことが多い。UA ブロックは**偵察段階の一部にしか効かない**

## 3. レート制限

- 対象は認証系パス(ログイン・パスワード再設定など)に絞る。サイト全体に掛けると、正規の連続操作(ページ表示+API)で誤ブロックする
- Free プランの制約の例(要確認):
  - ルール 1 本、時間窓 10 秒固定、ブロック時間 10 秒固定、カウント単位は IP のみ
  - 式で選べるフィールドが限られる(ホスト名を選べない場合は、パスを対象サービス固有のものに限定する)
- しきい値の目安: 10 秒に 5 回(人の操作は 10 秒に 1〜2 回。ログインは画面表示 + POST で 2 回)
- 実測: 通常の応答が 5 回続いた後に 429 が返ること、待機後に通常へ戻ること(`verification.md`)
- **アプリ側の回数制限と役割が違う**: エッジは短時間の連打を止め、アプリ側は分単位の総当たりを止める。どちらかだけでは不十分

## 4. 国別制限

- 利用者が国内中心なら、日本以外を遮断するだけで背景ノイズの大半が消える
- 例外(Webhook を送る海外サービス、検索エンジンのクローラ、決済の通知)があれば、先に洗い出してパスで除外する

## 5. プラン制限の確認観点

- ルール数の上限(使用数 / 上限)
- レート制限の時間窓・ブロック時間・カウント単位が固定か
- 式で使えるフィールド・関数
- 上位プランでないと使えない機能(ログ取得、マネージドルール)に依存した手順を書かない
