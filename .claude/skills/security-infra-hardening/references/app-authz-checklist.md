# 認可点検のチェックリストと点検書テンプレート

アプリ層(認可・認証フロー・回数制限)の点検用。インフラ層は `SKILL.md` の手順と他の references を使う。

## 1. 点検項目

### 1-1. 所有者の確認(IDOR)

ID・モデル・トークンを引数に取る**全エンドポイント**を表にする。

| ルート | 引数 | 所有確認の場所 | 判定 |
|---|---|---|---|

- 確認の型: 取得時にユーザー ID で絞る(`findByUser($userId, $id)`)/ 取得後に所有者を比較して 403/404 / ポリシー
- リクエストボディの ID(`robot_id` 等の参照先)も所有確認の対象。ルートの引数だけ見ない
- ID 引数が無いエンドポイントは、**現在のユーザー ID だけで動いているか**を確認する
- 他人のデータへの 404/403 の使い分け: 403 は存在を教える(L 扱いで指摘)
- 署名付き URL(メール認証・承認リンク): 署名・有効期限・ハッシュの比較が定数時間か

### 1-2. 管理者・ロールの境界

- 管理者認証が別ガード/別ルートか。IP 制限など外周の保護があるか
- 管理画面のロール(スタッフ等)ごとのアクセス制御の漏れ(ルートの allowlist の抜け)
- パスワード変更・MFA の有無

### 1-3. 環境依存ルート

- `local`/`debug` でだけ登録される**無認証のなりすましログイン**などのルート。環境変数の既定値が開発用(`APP_ENV=local` 等)になっていると、コンテナの再作成ミスで本番に露出する
- 確認: 本番の環境名、ルートキャッシュの有無、過去の露出期間のアクセスログ(0 件の確認)
- 是正案(影響の小さい順): ① 環境変数の既定値を本番側にする/未設定なら起動失敗 ② プロキシでパスを拒否 ③ ルートに追加条件 ④ ルート削除。採否は利用者に確認(開発で使うなら残す判断もありうる)

### 1-4. 認証フロー

- OAuth の `state`(CSRF 対策)の検証が素通りしていないか。stateless 指定になっていないか
- ログイン後のセッション再生成(セッション固定対策)
- パスワード再設定後の既存セッションの失効

### 1-5. ユーザー列挙

- パスワード再設定: 登録済み/未登録で**ステータスと文言が同じ**か。連続送信の別文言も目印になる
- ログイン: 文言が同じでも、未登録時にパスワード照合を省くと応答時間に差が出る(優先度は低い)
- 是正: 結果によらず同一応答(「登録されていればメールを送信しました」)。内部ログには結果を残す

### 1-6. 入力検証と増幅

- 未認証で、入力値ごとにキャッシュキーが増え、外部 API を多数呼ぶエンドポイント(増幅攻撃・外部サービスの遮断リスク)
- 範囲・件数に上限が無いパラメータ(期間、ページ、バケットサイズ)
- 画像アップロード: 拡張子・MIME・サイズ・配信時のヘッダ
- ユーザーが数を作れるリソース(アラート、ロボット等)の件数上限と競合

### 1-7. 例外メッセージの返却

- 本番で例外メッセージをそのままクライアントへ返していないか(内部情報の漏洩)

### 1-8. 問題なしと確認した範囲

SQL インジェクション(生 SQL のバインド、並び順列の許可リスト)、Mass assignment(`fillable`、`all()` の直渡し無し)、CORS(許可オリジン)、セキュリティヘッダー、停止ユーザーの扱い、プラン制限のサーバー側判定。

## 2. 重大度の基準

| 重大度 | 基準 |
|---|---|
| 高 | 認証なしで他人のデータ・権限・資金に到達できる(環境条件つきを含む) |
| 中 | 認証/回数制限の実効性が弱く、列挙・総当たり・増幅に使える |
| 低 | 条件が限られる、または影響が小さい |
| 情報 | 仕様と実装の不一致、将来の注意点 |

## 3. 点検書テンプレート

```markdown
# {システム名} 認可点検
## 0. 結論(要旨)
## 1. 対象・方法・範囲(対象コミット、点検方法、重大度の基準)
## 2. 指摘一覧(ID・重大度・題名の表)
## 3. 指摘の詳細
各指摘に: 事実 / 推測 / 影響 / 再現の考え方(ローカル・テストのみ) / 是正案
## 4. 問題なしと確認した範囲(IDOR の表、その他、回数制限の一覧)
## 5. 未確認事項(実機未検証のもの)
## 6. 利用者への依頼・判断事項
```

- 本番ログを使う確認は、**利用者の許可を得てから**読み取りのみで行い、結果に「誰が実施したか」を書く
